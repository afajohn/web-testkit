This is the **brain** of the system.

## 📄 Failure Context Schema

```ts
export type FailureCategory =
  | 'a11y-dom'
  | 'user-flow'
  | 'functional'
  | 'layout'
  | 'mobile'
  | 'seo';

export interface FailureContext {
  id: string;
  category: FailureCategory;

  url: string;
  pagePath?: string;

  selector?: string;
  target?: string;

  timing: 'initial-render' | 'post-hydration' | 'after-interaction';
  viewport: string;

  description: string;
  expected?: string;
  actual?: string;

  evidence: {
    screenshot?: string;
    domSnapshot?: string;
  };

  metadata?: Record<string, any>;
}
```

📌 This is **NOT runtime logic**
📌 This is a **contract** between tests and dashboard

# PHASE 3 — `reportFailure()` (THE WEAPON)

This is where your question really lived.
Yes, **this is core**. Yes, **it is mandatory**.

## 🎯 What `reportFailure()` Does

It:

1. Freezes the moment
2. Captures evidence
3. Produces a `FailureContext`
4. Hands it to your reporting pipeline

It does **NOT**:

* assert
* retry
* swallow errors
* guess fixes

Think: **forensic camera**

---

## 🗡️ `reportFailure()` – REQUIRED LOGIC

```ts
export async function reportFailure(page, partial) {
  const viewportSize = page.viewportSize();
  const viewport = viewportSize
    ? `${viewportSize.width}x${viewportSize.height}`
    : 'unknown';

  const domSnapshot = await page.content();

  const screenshotPath =
    `playwright-report/failures/${Date.now()}-${partial.id}.png`;

  await page.screenshot({
    path: screenshotPath,
    fullPage: true
  });

  return {
    id: partial.id,
    category: partial.category,
    url: page.url(),
    selector: partial.selector,
    target: partial.target,
    timing: partial.timing,
    viewport,
    description: partial.description,
    expected: partial.expected,
    actual: partial.actual,
    evidence: {
      screenshot: screenshotPath,
      domSnapshot
    },
    metadata: partial.metadata ?? {}
  };
}
```

📌 This must be callable from **any test**
📌 This must be **side-effect safe**

# PHASE 4 — HOW EACH TEST CATEGORY USES IT

This is the **most important section**. Read twice.

---

## ♿ A11Y / DOM TESTS

### Logic Rules

* ❌ No clicks
* ❌ No waits for visibility
* ❌ No user assumptions
* ✅ DOM truth only

### When to call `reportFailure()`

The **moment** a violation is detected.

### Required fields

* `category: 'a11y-dom'`
* `timing: 'initial-render'` or `'post-hydration'`
* `selector` (if available)

### Example

```ts
await reportFailure(page, {
  id: 'a11y-button-name',
  category: 'a11y-dom',
  selector: '.fc-megamenu',
  timing: 'initial-render',
  description: 'Button has no accessible name',
  expected: 'Button must have visible text or aria-label',
  actual: 'Accessible name is empty',
  metadata: {
    wcag: '4.1.2',
    impact: 'serious'
  }
});
```

🚨 If you can’t find it later — **that is expected**
🚨 The DOM snapshot is your source of truth

---

## 🖱️ USER FLOW / FUNCTIONAL TESTS

### Logic Rules

* ✅ User action defines failure
* ❌ DOM existence ≠ pass
* ❌ Scanner results ≠ user failure

### Pattern (MANDATORY)

```ts
try {
  await action();
  await assertion();
} catch (err) {
  await reportFailure(...);
  throw err;
}
```

### Example

```ts
try {
  await page.locator('a[href*="profile"]').click();
} catch (err) {
  await reportFailure(page, {
    id: 'user-profile-browse',
    category: 'user-flow',
    selector: 'a[href*="profile"]',
    timing: 'after-interaction',
    description: 'Profile browsing failed',
    expected: 'Profile page should open',
    actual: err.message
  });
  throw err;
}
```

🚨 These **must be reproducible**
🚨 If not reproducible, your test logic is wrong

---

## 📐 LAYOUT / RESPONSIVE TESTS

### Logic Rules

* ❌ Do not force selectors
* ❌ Do not hunt DOM nodes
* ✅ Measure behavior

### Example

```ts
await reportFailure(page, {
  id: 'mobile-layout-break',
  category: 'layout',
  timing: 'post-hydration',
  description: 'Mobile layout breaks at 375px',
  expected: 'Layout remains intact',
  actual: 'CLS exceeded threshold',
  metadata: {
    viewportTested: '375x667',
    cls: 0.32
  }
});
```

📌 `selector: N/A` is VALID
📌 This explains your earlier confusion
